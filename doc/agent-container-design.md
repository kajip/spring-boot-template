# Agent 実行コンテナの設計

**状態：設計のみ。未実装で、動作も検証していない。**

## 目的

Agent を無人で動かしても、人の名義で GitHub を操作できないようにする。

同じ Mac で動く Agent は、`gh` に残る人の認証情報を使って、レビューの関門を迂回できる。Agent を人の認証情報が無いコンテナで動かし、この経路を塞ぐ。当面の実行場所はこの Mac 上のコンテナとする。クラウドでの実行は対象外とする。

## 構成

```text
Mac（人の認証情報はここに留める）
└─ Docker（colima）
   └─ プロジェクトごとの Compose
      ├─ agent：Claude Code と開発環境
      └─ db   ：PostgreSQL
```

人が Mac から次のように起動する。

```sh
scripts/agent-run.sh "<Agent への依頼>"
```

## コンテナに渡すもの

| 対象 | 渡し方 | 用途 |
|---|---|---|
| リポジトリ | Agent 専用の clone をマウント | 作業対象 |
| App の秘密鍵 | 読み取り専用でマウント | 1 時間のトークンの発行 |
| `CLAUDE_CODE_OAUTH_TOKEN` | 環境変数 | Claude Code の認証 |

## コンテナに渡さないもの

| 対象 | 理由 |
|---|---|
| `~/.config/gh`、キーチェーン、`~/.ssh` | 人の名義を使わせない |
| Docker ソケット | Mac 側の権限を奪えるため |
| `ANTHROPIC_API_KEY` | 非対話実行で常に優先され、意図せず従量課金になるため |

## Claude Code の認証

Mac のログイン情報はキーチェーンにあり、コンテナからは読めない。Mac で `claude setup-token` を実行して長期トークンを発行し、`CLAUDE_CODE_OAUTH_TOKEN` として渡す。

トークンはリポジトリの外（`~/.config/<App 名>/`）に置き、`scripts/agent-run.sh` が環境変数へ渡す。

トークンの有効期限と、自動実行に関するサブスクリプションの利用条件は未確認である。実装の前に確認する。

## 実行時の動き

- **権限確認：** 開発用イメージに Claude Code を加え、権限確認なしで動かす。守りは GitHub 側の関門とコンテナの隔離に任せる。
- **Git の名義：** コミットの作者と push を、起動時から App に固定する。
- **作業場所：** Agent 専用の clone を使い、人の作業ツリーや開発中のコンテナと分ける。Compose のプロジェクトはフォルダごとに分かれるため、DB も分かれる。
- **Stop hook：** `run-check.sh` は Mac 上で Dev Container CLI を使う。コンテナ内では `./gradlew` を直接実行するように分岐させる。
- **スモークテスト：** Docker ソケットが無いためコンテナ内では実行せず、CI に任せる。

## ネットワーク制限

許可リスト方式とし、次の接続先のみを許す。一覧は実装時に実際の通信を確かめて確定する。

| 用途 | 接続先 |
|---|---|
| Claude Code | Anthropic の API と認証関連 |
| GitHub | `github.com`、`api.github.com` |
| Gradle | `repo.maven.apache.org`、`plugins.gradle.org`、`services.gradle.org` |
| npm | `registry.npmjs.org` |

設定には、コンテナに `NET_ADMIN` の権限が要る。Agent 自身が規則を書き換えられないように、起動時に root で適用してから権限を落とす必要がある。実現方法は実装時に検証する。

## 残る危険

| 危険 | 影響 | 備え |
|---|---|---|
| App の秘密鍵が読める | App の権限内で操作される。`doc/` と `src/test/` は無人でマージできる | 許可リストで持ち出しを抑える。漏洩時は GitHub で鍵を失効させる |
| Claude のトークンが読める | 利用枠を悪用される | 許可リストで持ち出しを抑える。漏洩時はトークンを失効させる |
| 許可先を経由した持ち出し | GitHub などの許可先へ送信できる | 完全には防げない。App の権限を最小に保つ |

公式資料も、権限確認なしで実行するときは、コンテナ内の認証情報を持ち出され得ると警告している。

## 実装後に確認すること

1. コンテナ内に人の認証情報が無く、`gh auth status` で人の名義が出ない。
2. 許可外の接続先へ通信できない。
3. Agent がネットワークの規則を変更できない。
4. App の名義で Pull Request を作成でき、[振り分け](agent-workflow.md) が想定どおりに動く。
5. Stop hook が `check` を実行し、失敗を Agent に返す。
6. 秘密鍵をマウントせずに起動すると、push に失敗する。

## 決めていないこと

- トークンの失効と更新の運用
- 複数の Agent を並列で動かすときの Gradle キャッシュの持ち方（共有するとロックで失敗することを確認済み）
- Agent への依頼の渡し方（コマンドの引数のほか、Issue から渡す方法）
